## Overview
This Instructables guide walks through building an Arduino based mini-sumo robot in 14 steps. The robots follow official mini-sumo rules with a 500 gram limit and a 10 cm by 10 cm footprint. Example programs make the robot flee, follow lines, or find and push objects. It suits older students who can build and code.

## Benefits for students
- Students build a working robot from parts and see their code drive it.
- Students program an Arduino with example sketches they can change.
- Students can test their robot in a sumo match.

## Benefits for teachers
- The 14 step guide gives a clear build order.
- A search summary says the guide includes notes for classroom discussion.
- A shopping list spreadsheet helps with ordering parts.

## Benefits for schools
- Parts cost money, and no price was found.
- Parts can be bought from the author's store or sourced from the spreadsheet.
- Setup takes days, and a teacher or IT will install the Arduino software.

## Getting started
- [ ] Find the SimpleSumo guide on Instructables.
- [ ] Read all 14 steps before buying parts.
- [ ] Order parts from the author's store or from the shopping list spreadsheet.
- [ ] Assemble the chassis and check it fits the 10 cm by 10 cm limit.
- [ ] Install the Arduino software on a computer.
- [ ] Upload one example sketch and test it.
- [ ] Weigh the finished robot against the 500 gram limit.

## Where is the AI?
The guide has no AI. The robot follows fixed Arduino code. Students build skills in logic and sensing as they program it to react to its surroundings.

## Privacy and safety
The materials do not state whether an account or internet is needed. The robot runs its code on the board. A teacher should check the Instructables site and any store account before students use them. One search note suggests grades 8-12 with adult supervision below high school, and the guide does not confirm it.

## Ideas by subject
### engineering
1. Build the chassis from the 14 step guide and check its size and weight against the rules.
2. Test the robot in a small ring and note where it fails.
3. Redesign one part of the chassis to push better.
4. Compare two builds in a class match and explain why one won.
5. Write a short build log that records each step and any fix.

### computer_science
1. Upload the example sketch that makes the robot flee and describe what it does.
2. Change a number in the line-following sketch and observe the result.
3. Read the sketch that finds and pushes objects and explain each part in plain words.
4. Write a short plan for a new behavior before changing the code.
5. Test and debug one change, and record what happened.
