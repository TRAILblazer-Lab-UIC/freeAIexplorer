## Overview
This is a six-lesson Key Stage 4 unit for ages 14 to 16 that uses the Raspberry Pi Pico microcontroller. Students program the Pico in MicroPython with the Thonny editor. Teachers in the blog post built motorised buggies and line-following cars. The unit matches US grades 9-11.

## Benefits for students
- Students program a real microcontroller in MicroPython.
- Students build motorised buggies and line-following cars.
- Students see how code changes a physical device.

## Benefits for teachers
- The unit has six lessons.
- Teachers in England can take a short training course.
- Teachers used the unit in after-school clubs and classes.

## Benefits for schools
- The unit is free. State schools in England can borrow class sets of 10 Picos from local Computing Hubs.
- Other schools buy Picos, which are low cost.
- A US offer of 1,000 free kits dated from 2021 and its current status is unknown.

## Getting started
- [ ] Find the Physical computing kits page from Teach Computing.
- [ ] Contact the local Computing Hub to borrow a kit. This option is for state schools in England.
- [ ] Ask IT to install the Thonny editor.
- [ ] Connect a Pico to a computer with USB.
- [ ] Run a first MicroPython program.
- [ ] Take the short teacher training course if available.
- [ ] Plan the buggy or line-following project.

## Where is the AI?
The unit has no AI. Students write MicroPython that reads inputs and controls motors. They build skills in logic and sensor data.

## Privacy and safety
Code runs on the Pico and students need no accounts. The internet is used only at setup. The research expected no student data collection but did not verify it. The official kit page did not load. Kit offers and loan terms are unconfirmed. Thonny must be installed on school machines. Confirm with IT that Thonny is installed before class.

## Ideas by subject
### computer_science
1. Run a first MicroPython program that blinks an LED on the Pico.
2. Change the timing in the program and watch the LED react.
3. Read a button and print a message when it is pressed.
4. Write a program that follows a short set of rules.
5. Debug a program that runs the wrong way.

### engineering
1. Build a motorised buggy and test its drive.
2. Add a sensor so the buggy can follow a line.
3. Test the buggy on tracks of different shapes and record how it did.
4. Redesign one part of the buggy to improve it.
5. Present the final build and explain the choices.
