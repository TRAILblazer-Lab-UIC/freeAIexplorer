## Overview
Sonic Pi is a free open source instrument that users play by writing code. It began as a University of Cambridge research project with the Raspberry Pi Foundation in 2012. It was designed to support both computing and music lessons in schools. Students write melodies and rhythms as code.

## Benefits for students
- Students hear their code as music right away.
- Students write melodies and rhythms with simple commands.
- Students see that code can be a creative tool.

## Benefits for teachers
- It was designed to support computing and music lessons.
- A web version needs no install.
- Setup takes only minutes.

## Benefits for schools
- The software is free and open source.
- Desktop apps are available for Windows, macOS, and Linux including Raspberry Pi.
- No IT involvement is listed.

## Getting started
- [ ] Open the Sonic Pi web version or download the app for school computers.
- [ ] Note that the downloads are version 5.0.0.
- [ ] Check that sound works on the computers.
- [ ] Play a short melody by writing a few lines.
- [ ] Try a loop that repeats a rhythm.
- [ ] Test the web version on a Chromebook before class. It was not tested.

## Where is the AI?
Sonic Pi has no AI. Students write code that plays sounds. They build sequencing and pattern skills as they repeat notes in loops.

## Privacy and safety
No account is needed, and the internet is used at setup. The desktop app is a local install and work stays on the device. The research found no privacy policy on the pages read. The browser version was labeled beta and was not tested. A teacher should check that headphones are available.

## Ideas by subject
### music
1. Write a short melody as code and play it back.
2. Create a drum rhythm with a repeating loop.
3. Change the notes of a scale and describe the new mood.
4. Layer a bass line under a melody.
5. Perform a coded piece for the class.

### computer_science
1. Write a program that plays notes in order.
2. Use a loop to repeat a rhythm four times.
3. Add a variable to change the tempo.
4. Find and fix a bug in a classmate's code.
5. Explain how each line changes the sound.
