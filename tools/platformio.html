PlatformIO

A professional embedded coding tool used as an alternative to the Arduino IDE.

ComputingRobotics

The privacy details for this item are unverified. Check which tools and accounts students will use before class.

Overview

PlatformIO is an open source ecosystem for embedded development. It offers an IDE extension and a Python based command line tool called Core. It includes a build system, package manager, library manager, serial monitor, debugging and unit testing. It supports many microcontroller boards and is aimed at advanced students who write C and C++.

Benefits

For students

  • Students use a tool that professional teams use.
  • Students manage libraries and debug their code.
  • Students work with many boards and frameworks.

For teachers

  • One tool covers many boards.
  • Unit testing and debugging teach good habits.
  • It suits an advanced high school class.

For schools

  • The core is free and open source.
  • Premium support is optional and was not priced on the pages read.
  • IT needs to install it. It is not Chromebook friendly.

Getting started checklist

Where is the AI in this product?

PlatformIO has no AI. It builds skills in text coding, debugging and testing. Students learn how a build system turns code into a program for a board.

Privacy and safety

No account is needed. The tool runs on the device and the internet is needed to download boards, libraries, and toolchains. The pages read did not describe telemetry. The footer links to a privacy policy that returned no readable content. The research did not confirm telemetry or account rules. A teacher should check the VS Code and extension settings with IT before class.

How this can be used for Computer Science
  1. Create a project and explain each file in it.
  2. Write C++ that blinks an LED.
  3. Add a library and use one function from it.
  4. Write a unit test for a small function.
  5. Use the serial monitor to debug a program.
How this can be used for Engineering and Design
  1. Build a program for a supported microcontroller board.
  2. Compare the same project on two boards.
  3. Use the debugger to find a timing problem.
  4. Record the memory use of a build.
  5. Document the setup so another team can repeat it.
