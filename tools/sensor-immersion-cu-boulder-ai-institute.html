Sensor Immersion (CU Boulder AI Institute)

A middle school science unit where students program micro:bit sensors.

AIComputingUnverified

The privacy details for this item are unverified. Check which tools and accounts students will use before class.

Overview

Sensor Immersion is a middle school science unit from the CU Boulder AI Institute. Students program a micro:bit with sound, soil moisture, and environmental sensors. They work in expert groups, with each group on one sensor, and then share findings with the class. The unit ends with a student-chosen display or investigation.

Benefits

For students

  • Students use sensors to investigate community problems.
  • Students become experts on one sensor and teach others.
  • Students meet computing and AI ideas as tools for science.

For teachers

  • The unit uses a driving question board and conceptual models.
  • A search snippet links the unit to NGSS MS-ESS3-3.
  • A week-long version was studied.

For schools

  • The unit cost is not stated.
  • Micro:bit kits and sensors are extra.
  • A search snippet suggests four or fewer students per micro:bit.

Getting started checklist

Where is the AI in this product?

The materials call this AI, but the listed functions are sensor data collection, thresholds, and data display. These run on the micro:bit. Students program the sensor, set a threshold, and display results. They use the data to answer a science question.

Privacy and safety

The data collected is sensor readings, and the micro:bit processes them on the device. The unit page does not describe accounts or data handling. Students program in MakeCode, and the research did not confirm whether it runs online or offline in this unit. The materials do not state whether accounts are needed. A teacher should check the MakeCode setup and confirm what it stores.

Ideas by subject

Select a subject to see five classroom ideas.

How this can be used for Science
  1. Use the soil moisture sensor to compare two plant pots.
  2. Record classroom sound levels at different times of day.
  3. Investigate a community problem with one sensor and report the findings.
  4. Build a conceptual model of how the sensor reading links to the problem.
  5. Share expert group findings with the class and compare them.
How this can be used for Computer Science
  1. Program a micro:bit to read a sensor in MakeCode.
  2. Set a threshold that triggers a warning on the display.
  3. Test the threshold at several values and choose the best one.
  4. Show the readings on the display in a clear way.
  5. Explain how the program turns a number into a decision.
How this can be used for Engineering and Design
  1. Design a display that shows sensor results to the class.
  2. Build a small enclosure that protects the micro:bit.
  3. Test the design and list two improvements.
  4. Plan an investigation with a student-chosen sensor.
  5. Present the final design and explain each choice.
