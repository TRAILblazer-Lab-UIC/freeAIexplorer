GitHub Codespaces for Education

A cloud coding environment that students open in a browser with no local setup.

AIComputing

Overview

GitHub Codespaces is a cloud development environment that runs on a GitHub virtual machine. Students reach it through a browser, VS Code, or the GitHub command line. Teachers using GitHub Classroom can make it the editor for assignments. Students then skip local setup and start coding.

Benefits

For students

  • Students code in a browser on any device, including Chromebooks.
  • Students get the same tools as every classmate.
  • Verified students get up to 180 core hours per month free.

For teachers

  • Each repository can carry a preset environment.
  • Teachers can launch assignments in Codespaces from GitHub Classroom.
  • Verified teachers get a separate free allowance.

For schools

  • Setup on student computers is not needed.
  • Classroom usage is charged to the organization that owns the classroom.
  • Students need GitHub accounts and must be age 13 or older.

Getting started checklist

Where is the AI in this product?

The AI is optional. GitHub Copilot offers code completion, and it is free for verified students. It runs in the vendor's cloud. Students can accept, change, or reject the suggestions, and the teacher can decide whether to allow it.

Privacy and safety

Every student needs a GitHub account and the internet at all times. GitHub says its services are not intended for anyone under 13. The vendor collects account data, code and files, usage and device data, and IP addresses. Data is stored in the US and other countries. VS Code telemetry is on by default in Codespaces, and the statement lists advertising and analytics partners for non-essential cookies. A school that supplies the accounts becomes the data controller. A teacher should turn off VS Code telemetry and check the age rule and the school's rules on student accounts.

How this can be used for Computer Science
  1. Open a prepared assignment repository and run the starter code.
  2. Fix a bug in a short program and commit the change.
  3. Work with a partner on one repository and review each other's code.
  4. Write tests for a small function in an AP style project.
  5. Compare code written with and without Copilot suggestions.
