Root Coding Robot (SAM Labs, formerly iRobot)

A small robot that drives on whiteboards and is programmed from a tablet.

Overview

iRobot Root is a small coding robot that drives on whiteboards and uses magnets to hold on. It is programmed from a tablet or phone app. Wikipedia describes it as an educational robot for children learning to code. iRobot acquired Root Robotics in 2019 and SAM Labs acquired the Root line in 2024.

Benefits

For students

  • Students program a robot that draws on a whiteboard.
  • Students start with blocks and move to text code in graduated levels.
  • Students can try the simulator in the coding app.

For teachers

  • The app offers three coding levels.
  • A Python SDK repository exists for older students.
  • The materials rate the teacher learning curve as moderate.

For schools

  • Launch coverage put the price at 129 USD, and no current price was confirmed.
  • The iOS app SAM Root needs iOS or iPadOS 13.0 or later.
  • Browser use needs Web Bluetooth.

Getting started checklist

Where is the AI in this product?

Root has no AI. It follows the code students write. Students build skills in sequencing and logic by planning a route on a whiteboard.

Privacy and safety

The materials do not state whether accounts are needed. The App Store privacy label for SAM Root lists analytics data not linked to the user, including coarse location, device ID, and product interaction. It also lists app functionality data. The SAM Labs privacy policy loaded no text, and an older iRobot policy snippet says it does not intentionally collect data from children under 13. That is a data rule, and analytics go through Google. A teacher should read the policy and the App Store privacy label before students use the app. A teacher should also test the robot on the classroom whiteboard.

How this can be used for Computer Science
  1. Program the robot to draw a square on a whiteboard.
  2. Use a block program to make the robot turn at a marked line.
  3. Compare a block program with its Python 3 version.
  4. Plan a route on paper and then code it.
  5. Debug a program that draws the wrong shape.
