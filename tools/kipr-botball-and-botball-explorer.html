KIPR Botball and Botball Explorer

A team robotics competition where students build and program autonomous robots.

ComputingRoboticsStays on the device

Overview

Botball is a team robotics competition for middle and high school students. Teams build and program two autonomous robots over a seven to nine week build period. Then they compete at regional tournaments. Each team gets a KIPR Wombat controller with LEGO pieces, metal parts, motors, servos, sensors and a camera. Teams write code in C, C++ or Java.

Benefits

For students

  • Students build and program robots as a team.
  • Students write real code in C, C++ or Java.
  • Students use a camera for computer vision tasks.

For teachers

  • Educator workshops run from January to March.
  • The Wombat serves a browser IDE over its own Wi-Fi.
  • Teams can use any device with a browser and Wi-Fi.

For schools

  • The official page lists no price.
  • The materials do not verify the registration fee or funding options.
  • The Wombat needs no school internet in use, apart from firmware updates.

Getting started checklist

Where is the AI in this product?

Botball has no AI in the materials. The robots follow the code that teams write. The camera can track colors, but the materials name no AI library. Students build skills in sensors, logic and planning.

Privacy and safety

No account is needed. A laptop joins the Wombat's own Wi-Fi network, and student work stays on the device. According to a search snippet of KIPR guides, the internet is only needed for firmware updates. Registration for the competition collects team contact details by form, and that form was not reviewed. A teacher should check that a laptop can join the Wombat network without losing school internet access. A teacher should also plan a safe space for robot testing.

How this can be used for Computer Science
  1. Write a first program that drives a servo and a motor.
  2. Use a sensor to make the robot stop at a line.
  3. Write a program that repeats a task twice.
  4. Use the camera to find an object by color.
  5. Trade code with a teammate and review it.
How this can be used for Engineering and Design
  1. Plan a robot design for the tournament task.
  2. Build two robots that share a goal.
  3. Test a design and record how often it completes the task.
  4. Redesign a weak part of the robot.
  5. Keep a team log of each build week.
